## 1. Summary
Title: Future Impact Decomposition in Request-level Recommendations (ItemA2C)
Authors: Xiaobei Wang, et al.
Venue/Year: KDD '24, August 25–29, 2024, Barcelona, Spain

Abstract/key contributions: Standard RL-based recommenders formulate a "request-level MDP": the user state updates once per list-wise recommendation request, and the policy outputs a whole list (slate) as one action. This is inconsistent with the user's actual item-wise behavior — a user attends to and reacts to one item at a time, and the causal effect of a given item on future engagement is not evenly distributed across the items in the slate. Standard request-level RL (e.g., A2C) optimizes the aggregate list-level cumulative reward and thereby loses information about which individual item drove the outcome. The paper's key contribution is Item-Decomposed Advantage Actor-Critic (ItemA2C): a framework that decomposes the actor's advantage loss into item-wise components while provably still optimizing exactly the same request-level cumulative-reward objective as standard A2C (the item-wise decomposition mathematically reconstructs the original request-level objective). Two decomposition/re-weighting strategies are proposed for splitting the shared future-value term V(s_{t+1}) across items in a list: a heuristic re-weighting (ItemA2C-W) that assigns more future credit to items with higher immediate reward, and a model-based re-weighting (ItemA2C-M) that learns the split via an adversarially trained neural weight model.

Methodology: Request-level MDP with item-wise observable rewards: state s_t (user features + history), action a_t = list of K items, reward R(s_t,a_t) = sum of observable item-wise rewards r_{t,k}, with the assumption that item-level state transitions are unobservable — only the aggregate request-level state transition is observed. A standard A2C backbone (critic V(s_t), actor pi(a_t|s_t)) is decomposed: the critic target Psi(s_t,a_t) = R(s_t,a_t) + gamma(1-d)V(s_{t+1}) is kept at request level (critic decomposition was tested and found not to help), but the actor's advantage is computed per item: Psi(s_t,i_{t,k}) = r_{t,k} + w_{t,k}·gamma·(1-d)·V(s_{t+1}), with weights w_{t,k} summing to 1 across the list so that summing the item-wise targets exactly reconstructs the request-level target. Two weighting schemes: (i) ItemA2C-W, a closed-form heuristic w_{t,k} = (alpha·r_{t,k}+(1-alpha))/(alpha·R(s_t,a_t)+(1-alpha)·K); (ii) ItemA2C-M, a neural weight model w(i_{t,k}, s_t, s_{t+1}, r_{t,k}) trained via an adversarial objective (the negative of the actor loss) to force the actor to learn from harder-to-attribute cases.

Main results: On two offline simulators (ML1M, KuaiRand1K, built on KuaiSim) ItemA2C-M achieved the best total reward and session depth, beating the strongest request-level baseline HAC by +27% reward / +20% depth on KuaiRand1K (statistically significant, p<0.05) and a smaller, non-significant +2.3%/+1.8% on ML1M. In a one-week live A/B test on an industrial video platform (100M+ daily users, refined-ranking stage, K=6), ItemA2C improved watch time, likes, follows, collects, and comments over request-level A2C, and ItemA2C-W further improved likes/follows/collects/comments (at a small, statistically insignificant watch-time cost); the deployment also drove a +0.028% DAU increase and a +0.016% weekly user-retention improvement.

## 2. Experiment Critique
Design: Offline pseudo-online simulation on ML1M (movie ratings) and KuaiRand1K (short video), using a KuaiSim-style session simulator with a trained click model providing rewards; five random seeds per configuration; baselines span SlateQ, DDPG, Supervision (BCE learning-to-rank), HAC (state-of-the-art hyper-action request-level actor-critic), and request-level A2C.

Statistical validity: KuaiRand1K improvements over HAC are reported as statistically significant (p<0.05); ML1M improvements are explicitly flagged by the authors as *not* statistically significant, with a plausible explanation offered (item-selection is "easier" on ML1M given fewer candidate items and more consistent user behavior) rather than an overstated claim.

Online experiments: A live, one-week A/B test at 10% traffic per arm on an industrial platform, comparing baseline, request-level A2C, ItemA2C, and ItemA2C-W, with per-metric percentage lifts and DAU/retention business-metric read-outs — a genuine, well-instrumented production experiment.

Reproducibility: Source code released (github.com/wangxiaobei565/ItemDecomposition); grid-search hyperparameters reported. Offline simulator and public datasets (ML1M, KuaiRand1K) are reproducible; the live deployment is not.

Overall: The authors run a component-analysis ablation (Table 4) explicitly testing whether decomposing the *critic* (not just the actor) into item-wise TD targets helps — it does not (itemA2C-W(C) does not surpass plain ItemA2C) — with a principled explanation (item interactions within a list can only be captured at the request level). This negative result, reported plainly, is a strength of the paper's experimental honesty.

## 3. Industry Contribution
Deployability: Deployed in the refined-ranking stage of a 100M+ DAU industrial video platform (candidate pool ~500, output list K=6); the actor is a 4-layer MLP over a 400-dim encoded user-request + candidate-item input, so inference cost is comparable to existing request-level actor-critic baselines (HAC/A2C) already running in production. The model-based weight model (ItemA2C-M) adds training-time complexity only — no extra inference-time parameters versus standard A2C, per the authors' claim.

Problems solved: Recovers item-level attribution information that is otherwise lost when an RL recommender only ever observes and optimizes a list-level (slate) reward, without requiring any change to the underlying request-level MDP data collection.

Engineering cost: Requires that item-wise rewards be observable and linearly aggregable into the list-level reward (an explicit, stated assumption) — the authors note this item-wise feedback stream is "usually easy to collect in most industrial recommender systems." The model-based reweighting variant (ItemA2C-M) needs an additional adversarially trained weight network and a more complex training loop (alternating fixed/free parameter updates between actor/critic and weight model), which is nontrivial additional training-pipeline engineering versus the heuristic ItemA2C-W variant.

## 4. Novelty vs. Prior Work
Claimed novelty: (1) Formal specification of the inconsistency between the system's request-level (list-wise) MDP view and the user's item-wise behavioral view; (2) an item-decomposed actor-critic that is mathematically proven to reconstruct the original request-level A2C objective exactly (no new learnable parameters, so no inference-time cost); (3) two schemes — heuristic and model-based/adversarial — for splitting a list's shared future-value term across the items that composed it, verified both offline and in a live A/B test.

Prior work cited (from Query 2 part 3): Ie et al. (2019), "SlateQ: A Tractable Decomposition for Reinforcement Learning with Recommendation Sets" — the closest prior item-decomposition method, critiqued for its unrealistic "single-choice" assumption (only one item in a slate can be consumed) that mismatches settings where all items may earn non-zero reward; S. Liu et al. (2023), "Exploration and Regularization of the Latent Action Space in Recommendation" (HAC) — the strongest request-level baseline, using a hyper-action embedding to represent a list; Lillicrap et al. (2016), "Continuous control with deep reinforcement learning" (DDPG); Mnih et al. (2016), "Asynchronous methods for deep reinforcement learning" (A2C backbone); Zhao et al. (2023), "KuaiSim: A comprehensive simulator for recommender systems"; Gao et al. (2022), "KuaiRand: An Unbiased Sequential Recommendation Dataset with Randomly Exposed Videos."

## 7. Reference Card
1. **Title, authors/company, venue, year, URL:** "Future Impact Decomposition in Request-level Recommendations," Xiaobei Wang, et al., KDD '24, Barcelona, Spain. URL: https://doi.org/10.1145/3637528.3671564. `nlm:f2d45264-e73c-42ed-9104-eccee63801bf`.
2. **Source type:** Academic (industry-scale evaluation; deployed and A/B-tested on an industrial platform).
3. **Direction:** D2.
4. **Problem setting:** List-wise (slate) recommendation formulated as a request-level MDP, where the system only observes request-level state transitions but individual items within a recommended list receive their own, individually observable immediate rewards.
5. **Objective and label definition:** Maximizes the standard infinite-horizon discounted cumulative reward E[sum gamma^i R(s_{t+i}, a_{t+i})]. Reward label: in the offline simulator, a binary click signal (click=1.0, no click=-0.2); online, a linear combination of watch-time quantile, like, follow, collect, and comment indicators. Horizon: episodes capped at 20 steps offline (per-user session); online, an infinite-horizon discounted framework with no explicit stated cap. Delay/censoring handling: Not specified in source.
6. **Prediction or incrementality:** Prediction only — the paper does not address incrementality. It states the goal as maximizing an RL policy's expected cumulative reward ("the goal is to maximize a cumulative reward over the expected future interactions") and separately notes, in its own motivating example, that "the causal effects of a certain item on the user's future interactions... are not evenly distributed in the list of exposure" — but this causal-language framing is used only to *motivate* the need for item-wise credit splitting, not to claim the paper estimates causal/incremental treatment effects. No counterfactual or treatment-vs-control estimation is performed; V(s_{t+1}) is a standard RL value estimate under the training policy, not a causal effect.
7. **Model architecture:** Actor pi_theta(i_{t,k}|s_t) and critic V(s_t) trained under a request-level A2C backbone; state s_t encodes user request + history; for online deployment, a 4-layer MLP actor over a 400-dim encoded (user request, candidate items) input; the model-based reweighting variant adds a separate neural weight model w(i_{t,k}, s_t, s_{t+1}, r_{t,k}) with softmax normalization across the list.
8. **Credit assignment (most thorough treatment in this batch):** This paper is the survey's most direct engagement with request-level-to-item-level credit assignment. Mechanism: the list-level reward is assumed linearly decomposable, R(s_t,a_t) = sum_k r_{t,k} (each item's immediate reward is separately observable). The *future* value V(s_{t+1}) — the expected future returns caused by having shown this entire slate — cannot be individually observed per item (item-level state transitions are unobservable under the request-level MDP), so the paper's core move is to split this single shared future-value term across the K items in the list via a weight vector w_{t,k} that sums to 1: Psi_w(s_t,i_{t,k}) = r_{t,k} + w_{t,k}·gamma·(1-d)·V(s_{t+1}). Because sum_k w_{t,k}=1, summing the item-wise targets exactly reconstructs the original request-level target Psi(s_t,a_t) — the decomposition is a provably lossless re-attribution of the same aggregate future-value estimate, not a new causal estimate. Three concrete decomposition rules are given: (a) equal-weight (w_{t,k}=1/K, alpha=0) — the naive baseline that ignores which item drove the value; (b) heuristic re-weighting (ItemA2C-W), which sets w_{t,k} proportional to the item's own immediate reward relative to the list's total immediate reward (alpha in [0,2] interpolates between equal-weight and pure-reward-proportional splitting; alpha in [1.0,1.5] performed best empirically) — this is the paper's closest analogue to "attributing a long-horizon outcome back to an individual item-level decision," but it is explicitly a heuristic assumption (items with better immediate feedback are assumed, not proven, to have proportionally larger future impact); (c) model-based reweighting (ItemA2C-M), which learns w_{t,k} = w(i_{t,k}, s_t, s_{t+1}, r_{t,k}) via a neural network trained adversarially against the actor (the weight-model loss is the negative of the actor loss, forcing the actor to face "harder," more discriminating attributions), softmax-normalized to sum to 1. Empirically ItemA2C-M > ItemA2C-W > equal-weight ItemA2C on both offline benchmarks and online, indicating that a learned, non-uniform decomposition of future impact captures more useful signal than either an aggregate list-level value or a hand-specified heuristic split. The paper also ran the counter-experiment of decomposing the *critic's* TD-target learning to the item level (not just the actor's advantage) — this failed to outperform the actor-only decomposition, and the authors conclude that item-item interactions within a list can only be captured by keeping the critic's value estimate at the request (list) level; only the actor-side advantage/attribution should be decomposed. This is exactly the kind of decomposition the project needs conceptually (attributing a shared future-value/long-horizon signal to individual items within a slate), but note two limits for direct transfer: the decomposition splits a *value estimate* (RL policy value), not a *causal/incremental* effect, and the "future impact" being split is the standard RL bootstrapped V(s_{t+1}), which already aggregates all downstream discounted rewards rather than isolating a specific delayed outcome like 7–30 day retention.
9. **Training data and counterfactual handling:** Training samples are request-level MDP transitions (s_t, a_t, r_{t,1..K}, s_{t+1}, done); for offline evaluation an on-policy pseudo-online simulator is used (agent interacts with a learned click-probability user simulator); no explicit off-policy/counterfactual correction (e.g., importance sampling) is described for the offline experiments, and the online A/B test uses direct randomized traffic assignment rather than counterfactual estimation.
10. **Offline and online evaluation:** Offline — pseudo-online training/evaluation in a session simulator (KuaiSim-style) on ML1M and KuaiRand1K, reporting undiscounted total reward and session depth averaged over the last 100 episode steps (min. 320 user episodes) across 5 random seeds. Online — one-week live A/B test on an industrial platform's refined ranking stage (K=6, ~500 candidates), 10% traffic per arm, reporting relative lifts in watch time, like, follow, collect, comment, DAU, and weekly retention.
11. **Reported gains:** Offline (KuaiRand1K): ItemA2C-M total reward 16.03±0.53 / depth 16.59±0.45 vs. HAC (best request-level baseline) 12.65±0.26 / 13.72±0.22 — statistically significant +27% reward, +20% depth (p<0.05). Offline (ML1M): ItemA2C-M reward 17.94±0.47 vs. HAC 17.53±0.13 — a marginal, non-statistically-significant +2.3% reward, +1.8% depth. Online (industrial platform, vs. request-level A2C): ItemA2C +1.103% like, +0.300% follow, +0.963% collect, +0.221% comment, +0.129% watch time; ItemA2C-W (alpha=1) vs. ItemA2C: +0.451% like, +0.636% follow, +0.616% collect, +0.258% comment, -0.013% watch time (statistically insignificant decrease). Platform-level: +0.028% DAU, +0.016% weekly user retention.
12. **Applicability to a two-sided dating recommender:** Not addressed in the paper (single-sided video consumption, no reciprocity/congestion/fairness treatment). The item-wise future-impact decomposition mechanism is directly relevant as a candidate technique for attributing a slate-level retention/revenue signal down to the decision of showing one specific candidate profile B within a recommended list, which is exactly the project's Q2 credit-assignment need.
13. **Unverified claims:** The assumption that list-level reward is a strictly linear aggregation of item-wise rewards (R(s_t,a_t) = sum r_{t,k}) is stated as an assumption of the MDP formulation, not empirically validated against real, possibly non-linear (e.g., interference/complementarity) effects among items in a slate. The claim that item-wise reward streams are "usually easy to collect in most industrial recommender systems" is asserted without a supporting citation or measurement.

## Project Relevance
This paper is the survey's most direct treatment of **Q2** (attributing a delayed/aggregate, list-level outcome to an individual item-level decision) among the four papers in this batch — its explicit item-wise decomposition of a shared future-value term, with both a heuristic and a learned/adversarial weighting scheme, is a directly transferable pattern for the project's core problem of attributing retention/revenue credit to showing one candidate profile B to viewer A within a ranked slate. It also speaks to **Q4** (how to combine short-term (immediate reward r_{t,k}) and long-term (future value V(s_{t+1})) signal heads) via its explicit additive decomposition Psi_w = r_{t,k} + w_{t,k}·V(s_{t+1}). It does **not** address **Q5** (causal/incremental effect) — despite using causal language ("causal effects... not evenly distributed") to motivate the problem, the method itself decomposes an RL value estimate, not a measured incremental effect — nor **Q7** (two-sided market, reciprocity, congestion, fairness), which is entirely absent. The negative critic-decomposition result (Table 4, itemA2C-W(C)) is a useful cautionary finding for the project: decomposing the value function itself, as opposed to the advantage/attribution used for the actor update, may not help when items interact within a shared request/slate — worth testing directly against the project's own slate structure.
