### **(2) Core Problem and Key Contribution**
* **Core Problem:** Optimizing user retention in Sequential Recommender Systems (SRSs) using Reinforcement Learning (RL) faces severe offline learning challenges [1, 3]. Online trial-and-error exploration risks losing users by recommending inappropriate items [3]. Offline RL methods suffer from value estimation instability ("Deadly Triad" in value-based RL) or unbounded variance in counterfactual policy evaluation (policy-based RL) [3]. While Decision Transformers (DT) cast offline RL as autoregressive sequence modeling to avoid these issues [4, 5], applying DT directly to recommendations presents three major bottlenecks [1, 4]:
  1. *Deficiency in Reward Modeling:* Standard scalar reward embeddings ignore the partial order relationships between retention values [4].
  2. *Data Discrepancy during Generation:* Training uses diverse rewards, but inference conditions on maximum rewards, causing out-of-distribution (OOD) issues and underutilizing small-reward samples [4].
  3. *Unreliable Offline Evaluation:* Importance-weighted offline evaluation leads to high variance [4].
* **Key Contributions:**
  1. **DT4Rec Framework:** Proposes a Decision Transformer framework tailored for user retention optimization in sequential recommendations [1, 4].
  2. **Auto-Discretized Reward Prompt:** Introduces a reward prompt module using weighted aggregation over meta embeddings to preserve the partial order of retention values [1, 6].
  3. **Weighted Contrastive Supervised Policy Learning:** Employs a weighted contrastive loss that treats small-reward actions as negative samples, preventing OOD generation issues and fully leveraging low-reward data [1, 13–15].
  4. **Robust Offline Metrics:** Introduces two stable offline metrics for evaluating retention—Model-Based User Return Score (MB-URS) and Similarity-Based User Return Score (SB-URS) [1, 17–19].

### **(3) Proposed Method or Architecture in Detail**
* **MDP Formulation & Input Sequence:**
  * Trajectory sequence: \\(\tau = [s_1, a_1, r_1, \dots, s_t, a_t, r_t]\\) [5, 7].
  * *State (\\(s_t\\)):* User interaction history [7].
  * *Action (\\(a_t\\)):* Recommendation list generated by recommendation policy \\(\pi: s_t \to a_t\\) [7].
  * *Reward (\\(r_t = e_t\\)):* User retention reward, defined as future log-in frequency across \\(K\\) timesteps: \\(e_t = \sum_{k=1}^K \mathbb{1}[\text{log-in}_{t+k}]\\) [7].
* **Four Core Architectural Blocks:**
  1. *Auto-Discretized Reward Prompt Module:* Maps scalar retention reward \\(r\\) through a neural weighting network \\(z = \phi(W \sigma(w \hat{r}) + \alpha \sigma(w \hat{r}))\\) to aggregate meta embeddings \\(M_b\\) into a smooth, order-preserving reward vector \\(\hat{r} = \sum_{b=1}^B z_b M_b\\) [6].
  2. *State-Action Encoder:* Encodes dynamic-length recommendation item sets using a GRU layer to handle varying action sequence lengths efficiently [8, 9].
  3. *Transformer Decision Block:* Uses unidirectional Transformer layers with Multi-Head Self-Attention, skip connections, and GELU activation to model dynamic user interest shifts [9–11].
  4. *Action Decoder:* Uses GRU to decode target item embeddings from contextual transformer representations [10].
* **Weighted Contrastive Supervised Policy Learning:**
  * Combines Cross-Entropy loss \\(\mathcal{L}_{\text{CE}}\\) with Weighted Contrastive Loss \\(\mathcal{L}_{\text{CL}} = -\sum_{v^- \in \Upsilon} \hat{v}(\tilde{a}^-) f_s(\tilde{a}, \tilde{a}^-)\\) [13–16].
  * Weights negative samples inversely proportional to their retention rewards to penalize recommending low-retention item sequences [11].
* **Credit Assignment Mechanics:**
  * Does **not** perform explicit multi-touch credit assignment to individual items or swipes [5, 13–15].
  * Instead, DT4Rec models retention autoregressively by mapping prior trajectories \\((r_t, s_t, a_t)\\) to future item generation under conditional reward prompts [4, 5].

* **Comparison Baselines:**
  * **BERT4Rec:** Sequential recommendation model using bidirectional Transformers [15].
  * **SASRec:** Sequential recommendation model using unidirectional Transformers [15].
  * **LIRD:** Deep RL baseline using an Actor-Critic (AC) framework combining policy gradients and DQN [15].
  * **TopK:** Policy-gradient offline RL recommender using REINFORCE with importance-sampling correction [15].
  * **DT4Rec-R:** Ablation variant of DT4Rec trained without considering retention rewards [15].

### **(5) Key Quantitative Results with Numbers**
* **Prediction Accuracy Benchmark (Table 2):**
  * *IQiYi Dataset:* DT4Rec achieved **HR@5 = 0.2524**, **NDCG@5 = 0.1601**, **HR@10 = 0.3601**, **NDCG@10 = 0.1983** (statistically significant improvements over SASRec 0.2312 / 0.1478 / 0.3385 / 0.1821 and BERT4Rec 0.2104 / 0.1325 / 0.3150 / 0.1628) [16, 17].
  * *ML-1m Dataset:* DT4Rec achieved **HR@5 = 0.4331**, **NDCG@5 = 0.4185**, **HR@10 = 0.5679**, **NDCG@10 = 0.3342** (statistically significant improvements over SASRec 0.4052 / 0.3983 / 0.5409 / 0.3123 and BERT4Rec 0.3817 / 0.3806 / 0.5286 / 0.2769) [16, 17].
* **User Retention Benchmark Performance (IQiYi Dataset, Table 3):**
  * **Model-Based User Return Score (MB-URS, higher is better):** DT4Rec = **6.05** vs. LIRD (**5.63**), TopK (**5.41**), DT4Rec-R (**5.16**) [16].
  * **Similarity-Based User Return Score (SB-URS, higher is better):** DT4Rec = **72,270** vs. LIRD (**63,572**), TopK (**61,045**), DT4Rec-R (**52,131**) [16].
  * **Improved User Retention (IUR, higher is better):** DT4Rec = **26.0%** relative user retention improvement vs. LIRD (**17.3%**), TopK (**12.7%**), DT4Rec-R (**7.5%**) [16].
  * **No Return Count (NRC, lower is better):** DT4Rec = **1.5%** user churn vs. LIRD (**1.9%**), TopK (**2.0%**), DT4Rec-R (**2.6%**) [16].
* **Ablation Study (IQiYi Dataset, Table 4):**
  * *Without Contrastive Learning (`w/o contrastive`):* SB-URS dropped to **65,175** (**-9.82%**), MB-URS dropped to **5.68** (**-6.11%**), IUR dropped to **18.3%** (**-29.6%** relative drop) [14].
  * *Without Contrastive Weighting (`w/o weight`):* SB-URS dropped to **69,316** (**-4.09%**), MB-URS dropped to **5.79** (**-4.30%**), IUR dropped to **20.6%** (**-20.8%**) [14].
  * *Without Auto-Discretized Reward Prompt (`w/o auto-dis`):* SB-URS dropped to **70,953** (**-1.82%**), MB-URS dropped to **5.96** (**-1.49%**), IUR dropped to **24.2%** (**-6.9%**) [14].

### **(6) Limitations, Failure Modes, or Negative Results**
1. **Out-of-Distribution (OOD) Generation Bottleneck in Vanilla DT:** In standard Decision Transformers, generating recommendations conditioned strictly on maximum reward ignores samples with smaller rewards during policy inference [4, 18, 19].
2. **Performance Collapse without Reward Prompts:** Removing retention rewards (`DT4Rec-R`) caused MB-URS to collapse from **6.05 down to 5.16** and IUR to drop from **26.0% down to 7.5%**, proving that sequence modeling alone without reward prompts fails to capture long-term user preferences [15, 16].
3. **Instability of Offline RL Baselines:** Traditional offline RL baselines (LIRD, TopK) suffered from the "Deadly Triad" instability and high importance-sampling variance, underperforming DT4Rec across all retention metrics [3, 20].

### **(D) Application to Dating Platform Retention (Replacing Last-Touch N7)**
* **How it Improves on Last-Touch:** Last-touch heuristically assigns 100% of the binary N7 retention label to recent swipes post-hoc. DT4Rec replaces post-hoc last-touch rule assignment by modeling candidate profile generation autoregressively using a Decision Transformer [4, 5]. It conditions recommendation generation on a target retention prompt \\(r\\) (e.g., active on day 7), generating candidate profiles whose sequence probability maximizes the desired return [4, 6–7].
* **Dating Platform Mapping (Swipe / Match / Conversation):**
  1. *State (\\(s_t\\)):* Encodes historical swiping, matching, and 4-way conversation interactions using GRU action encoders and Transformer decision blocks [5, 8–11].
  2. *Action (\\(a_t\\)):* The generated candidate profile list for swiping [3, 8].
  3. *Auto-Discretized Reward Prompt (\\(r\\)):* Encodes the desired 7-day retention target (\\(e_t\\)) using meta-embedding aggregation \\(\hat{r} = \sum_{b=1}^B z_b M_b\\) to maintain partial ordering across retention levels [3, 9].
  4. *Weighted Contrastive Policy Learning:* Treats low-retention trajectories (e.g., swiping sessions resulting in churn) as weighted negative samples (\\(\mathcal{L}_{\text{CL}}\\)), steering the ranker away from generating profile lists that mirror past low-retention swiping patterns [13–15].

---

### **(E) Selection-Bias & Confounding Handling**
1. **Auto-Discretized Reward Prompt Module:** Translates scalar retention rewards \\(r\\) through a neural weighting network \\(z = \phi(W \sigma(w \hat{r}) + \alpha \sigma(w \hat{r}))\\) to aggregate meta-embeddings, preserving the partial ordering between different retention values [4, 9].
2. **Weighted Contrastive Supervised Policy Learning:** Addresses out-of-distribution (OOD) generation issues (where inference conditions on maximum rewards while training encounters diverse rewards) by incorporating low-reward trajectories as weighted negative samples [4, 13–15]:
   \\[\mathcal{L}_{\text{CL}} = -\sum_{v^- \in \Upsilon} \hat{v}(\tilde{a}^-) f_s(\tilde{a}, \tilde{a}^-)\text{}\\]
   This prevents the model from ignoring low-reward data during autoregressive training [13–14, 27–28].
3. *Note:* Does not use explicit Inverse Propensity Weighting (IPW) or causal graph debiasing for user swiping selection bias [3–4].
